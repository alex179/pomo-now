## 1. 系统架构 (System Architecture)

本方案采用经典的 **客户端-服务端 (Client-Server)** 架构。

- **前端 (Client)：** 采用 **React Native** 构建跨平台移动应用 (iOS/Android)，负责所有 UI 渲染、用户交互、计时器逻辑和本地数据缓存。前端还需要集成 Apple Authentication 框架来获取认证凭证。
- **后端 (Server)：** 采用 **Go + Gin 框架** 实现一套高性能的 RESTful API 服务。后端服务需要与 Apple 的身份认证服务器通信，以验证客户端发来的 `identityToken`。
- **数据库 (Database)：** 采用 **MySQL** 关系型数据库，持久化存储所有用户数据。

## 2. 技术选型 (Technology Stack)

| 层面     | 技术栈           | 理由                                                                                                                                                                                                                         |
| :------- | :--------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **前端** | **React Native** | 1. **跨平台开发**：一套代码覆盖 iOS 和 Android，节约成本。 <br> 2. **生态成熟**：社区有成熟的 "Sign in with Apple" 库可供使用。                                                                                         |
| **后端** | **Golang + Gin** | 1. **极致性能**：Go 是静态编译型语言，运行效率极高，非常适合构建高性能 API。<br> 2. **高并发能力**：原生的 Goroutine 协程机制可以轻松应对大量并发请求。<br> 3. **部署简单**：可编译成单一二进制文件，极易于 Docker 容器化部署。 |
| **数据库** | **MySQL** | 1. **广泛普及**：全球最流行的开源关系型数据库，社区庞大，文档和解决方案丰富。<br> 2. **稳定可靠**：经过长期和大规模的市场验证，稳定性和可靠性极高。<br> 3. **生态兼容**：与 Go 语言生态（如 GORM 等 ORM 框架）兼容性良好。 |
| **部署** | **Docker + AWS/GCP** | 1. **环境一致性**：Docker 容器化部署，确保开发、测试、生产环境的一致性。<br> 2. **高可用与伸缩性**：使用成熟的云服务商提供高可用、可伸缩的服务器和数据库服务。                                                     |

## 3. 数据库模式设计 (MySQL Schema)

为支持 Apple ID 登录，`users` 表结构需要进行调整。

- **`users` (已更新)**
    ```sql
    CREATE TABLE users (
        id VARCHAR(36) PRIMARY KEY,
        -- Email and password are now nullable to support Apple ID sign-in
        email VARCHAR(255) UNIQUE,
        password_hash VARCHAR(255),
        -- Stores the unique user identifier from Apple
        apple_user_id VARCHAR(255) UNIQUE,
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        -- Ensures a user has at least one sign-in method
        CONSTRAINT chk_auth_method CHECK (password_hash IS NOT NULL OR apple_user_id IS NOT NULL)
    );
    ```

- **`tasks`**
    ```sql
    CREATE TABLE tasks (
        id VARCHAR(36) PRIMARY KEY,
        user_id VARCHAR(36) NOT NULL,
        title VARCHAR(255) NOT NULL,
        estimated_pomodoros INT DEFAULT 1,
        status ENUM('pending', 'in_progress', 'completed') DEFAULT 'pending',
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        completed_at TIMESTAMP NULL,
        FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
    );
    ```

- **`pomodoro_sessions`**
    ```sql
    CREATE TABLE pomodoro_sessions (
        id VARCHAR(36) PRIMARY KEY,
        user_id VARCHAR(36) NOT NULL,
        task_id VARCHAR(36),
        duration_minutes INT NOT NULL,
        type ENUM('focus', 'short_break', 'long_break') NOT NULL,
        ended_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
        FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE SET NULL
    );
    ```

## 4. API 接口设计 (API Endpoints)

为支持 Apple ID 登录，认证相关的 API 需要扩展。

- **用户认证 (`/api/auth`)**
    - `POST /register`：传统邮箱密码注册。
    - `POST /login`：传统邮箱密码登录。
    - **`POST /apple/login` (新增):**
        - **请求体 (Request Body):** `{ "identityToken": "...", "fullName": { "givenName": "John", "familyName": "Appleseed" } }`
        - **流程:**
            1.  客户端发送从 Apple 获取的 `identityToken` 到此端点。
            2.  后端验证 `identityToken` 的有效性。
            3.  使用 token 中的 `sub` (subject) 字段作为 `apple_user_id`。
            4.  查询数据库中是否存在该 `apple_user_id` 的用户。如果存在，则登录成功；如果不存在，则使用 `fullName` 和 token 中的 email 信息创建新用户。
            5.  返回用于会话管理的 JWT (JSON Web Token)。
    - `GET /me` (需要认证中间件)

- **任务管理 (`/api/tasks`)**
- **会话记录 (`/api/sessions`)**
- **统计 (`/api/stats`)**

## 5. 开发路线图 (Development Roadmap)

建议分阶段进行开发，以实现快速迭代和市场验证。

- **第一阶段 (MVP - 1个月)：** 实现核心计时器功能和本地化的任务管理。
- **第二阶段 (云同步 - 2周)：** 开发用户账号系统（包含邮箱和 Apple ID 登录），实现任务和历史记录的云端同步。
- **第三阶段 (完善与激励 - 3周)：** 实现完整的统计分析页面和成就系统。
